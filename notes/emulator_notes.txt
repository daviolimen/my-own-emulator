Okay, so before we hop into programming, we need to define how exactly our architecture will work. Here we go:

1. Hardware Specifications

I want something simple, but that would be good enough to scale up without many software problems, so:

* 16-bit architecture
* 8 general-purpose registers + SP + PC + FLAGS (negative, zero, positive, halt)
* 64KiB RAM (maximum indexable memory for 16-bit)
* Only the 8 general-purpose registers are used in the assembly, SP, PC and FLAGS are internally controlled

2. Instruction Set

* Simple and fixed-length (like RV32I)
* 16-bit instructions
* 20-30 instructions (5-bit opcode)

So here we go:

Immediate instructions:

* LLI RX, imm8 (RX[7:0] <- imm8)
* LUI RX, imm8 (RX[15:8] <- (imm8 << 8))
* LDI RX, imm16 (RX <- imm16) (this is actually more of an assembly macro that will become 2 instructions, LLI and LUI)

OBS: The immediate value may be a label, so the register will be loaded with the absolute address of the instruction
that follows the said label

Memory instructions:

* MOV RX, RY (RX <- RY)
* MOV RX, [RY] (RX <- mem[RY])
* MOV [RX], RY (mem[RX] <- RY)

Arithmetic-Logic instructions:

* NOT RX, RY (RX <- ~RY)
* ADD RX, RY, RZ (RX <- RY + RZ)
* SUB RX, RY, RZ (RX <- RY - RZ)
* AND RX, RY, RZ (RX <- RY & RZ)
* OR  RX, RY, RZ (RX <- RY | RZ)
* XOR RX, RY, RZ (RX <- RY ^ RZ)
* SHL RX, RY, imm (RX <- (RY << imm))
* SHR RX, RY, imm (RX <- (RY >> imm))
* CMP RX, RY (set flags according to the result of RX - RY)

Jump instructions:

* JMP RX (unconditional jump)
* JEQ RX (jump if flag Z is set)
* JNE RX (jump if flag Z is not set)
* JGT RX (jump if flag P is set)
* JGE RX (jump if flag N is not set)
* JLT RX (jump if flag N is set)
* JLE RX (jump if flag P is not set)

Stack instructions:

* PUSH RX (push RX to the top of the stack)
* POP RX (pop from the top of the stack to RX)

OBS: SP starts at 0xFFFF (last memory address) and grows down

Extra instructions:

* NOP (no operation)
* HLT (halt operation)

3. Binary encoding of instructions:

* 0 or 1 -> actual opcode
* X -> bits to encode RX
* Y -> bits to encode RY
* I -> bits to encode imm
* M -> bits to control between register and mem[register]
* . -> unused / ignored

* LLI  = XXX00000 IIIIIIII
* LUI  = XXX00001 IIIIIIII
* MOV  = ...00010 MXXXMYYY
* NOT  = XXX00011 .YYY....
* ADD  = XXX00100 .YYY.ZZZ
* SUB  = XXX00101 .YYY.ZZZ
* AND  = XXX00110 .YYY.ZZZ
* OR   = XXX00111 .YYY.ZZZ
* XOR  = XXX01000 .YYY.ZZZ
* SHL  = XXX01001 .YYYIIII
* SHR  = XXX01010 .YYYIIII
* CMP  = XXX01011 .YYY....

4. Debugging

So I added a debugging mode for the emulator, that basically just allows you to go instruction by instruction through
what the computer is doing. There are basically 4 commands:

N -> go to the next instruction
R [num] -> print the value of the register [num]
M [num] -> print the value of the memory at address [num]
W [num] -> wait for [num] steps

OBS: The debugger shows the state after each instruction, so the current instruction that it shows has already been
executed

5. Memory Mapping

I have 64KiB of RAM, it is a lot for simple computation, but not much for graphics. The most accurate way to handle this
would be like old consoles used to do with tile-based graphics. But as I just want to get things to be as simple as
possible, I guess I will just map the screen to some region in memory. So here it is:

0x0000 - 0x1FFF -> static memory defined with the assembly directives
0x2000 - 0x9FFF -> 256x128 monochromatic framebuffer to be mapped onto a window
0xA000 - 0xFFFF -> stack region
